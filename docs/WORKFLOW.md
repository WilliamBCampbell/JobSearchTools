# Operating workflow

Use this sequence with any assistant that can read/write local files and call the installed tools. The workflow does not depend on a particular model, hidden memory, commercial agent service or the original author's computer.

## 1. Establish the working environment

Read INSTALLATION.md. Confirm local file access, JobSpy tool discovery, an ordinary web-research route and the Playwright extension connection. Run the local test form before touching an employer application. Record versions and known limitations privately. A client with file tools but no command execution can edit the JSON records; the user must run the validation and rendering commands.

## 2. Build the candidate record

Follow ONBOARDING.md and CAREER-LIBRARY.md. Collect original resumes, project descriptions and writing samples. Inventory every employer and project, ask about ownership and outcomes, and confirm constraints. Source-backed facts and unverified drafts must remain distinguishable. Do not promote an AI-generated summary into a primary source.

The minimum usable record has an employment/education timeline, several concrete examples, explicit skill boundaries and location/work preferences. Contact details and sensitive application facts live separately. Mark onboarding complete only after the candidate reviews the overview and unresolved questions.

## 3. Search and evaluate

Use JobSpy for discovery; inspect logs and error fields before treating fewer results as fewer jobs. Fetch full details, verify the official posting, and deduplicate against the tracker. Compare requirements to the whole library. A shortlist records evidence-backed strengths, gaps, compensation type, location, travel, posting status and check time. Ten requested leads does not justify ten weak matches; report fewer when necessary.

## 4. Prepare one application

Create applications/COMPANY-REQUISITION/. Save the listing, requirements, reviewed evidence selection, planned resume bullets, tailored resume/cover letter, question answers and document hashes. Check the actual form before drafting optional material. Salary, references, start date, terms and sensitive disclosures are candidate decisions, scoped appropriately. Do not copy an old salary into a new role silently.

Render the PDFs and inspect every page. Verify contact links, dates, titles, no clipping, readable type and useful page coverage. Run the claim audit. Present the package for review and retain the approved version.

## 5. Fill and review

Use Chrome through Playwright MCP, or supply a copy-ready manual packet if the site fails. The agent reads the current page, fills a section, verifies values, and advances only through known intermediate actions. Recheck work-history parsing and file names. Do not assume a form is complete because the resume uploaded.

The candidate normally submits. If the candidate expressly authorizes submission, verify required fields and material acknowledgments first, submit once and observe the result. Human CAPTCHA is not a failure of the workflow; repeated rejection after verification is a reason for manual handling, not evasion.

## 6. Reconcile and track

Save a receipt with evidence type, employer/role, time, actual document hashes and observed result. Distinguish candidate-reported submission from an independently observed receipt. Unknown outcomes block retries. Append tracker events; preserve prior events, documents and interview history.

Read email/calendar only with the candidate's permission and available connectors. Match messages to requisitions. An email announcing another job is not a receipt. A cancelled interview is not a completed interview, and a second round is not a second company.

## 7. Prepare interviews and resume later

Build a concise sheet from the posting, invitation, earlier conversations and the full library. Separate real stories from proposed approaches. Explain why product facts matter to the customer's work. After an interview, capture the candidate's debrief, new facts, follow-ups and next steps without inventing feedback.

Update session.json with active application, current step, paths, pending questions, authorizations and outcome uncertainties. Never include cookies, credentials, verification codes or private meeting access links. The next agent rechecks the browser and evidence rather than assuming the session survived.

## Authority and checkpoints

Career library: factual authority. Application package: exact employer-specific answers and approved files. Tracker events and receipts: application outcome authority. Session handoff: navigation aid, not a source of new career truth. Human review: approval of the specific material/action, not an unlimited permission for future jobs.
